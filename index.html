증상

모바일 환경에서 결제 창이 팝업이 아닌 페이지 이동 방식으로 동작하면서, 결제 이후 기존 주문 상태가 유지되지 않는 문제가 발생했습니다.

원인

페이지 리다이렉트 과정에서 기존 상태(주문 데이터)가 초기화되어 결제 완료 후 주문 처리가 정상적으로 이어지지 않았습니다.

결제 요청 전에 주문 데이터를 sessionStorage에 저장하고, /checkout/mobile-payment 리다이렉트 페이지에서 결제 성공 여부를 확인한 뒤 해당 데이터를 기반으로 주문 처리를 수행하도록 구현했습니다.

Frontend Fullstack 개인

친구들과의 약속이나 여행을 준비할 때, 여러 장소를 정리하고 동선을 계획하는 과정이 번거롭다는 점에서 출발한 프로젝트입니다. 굿데이는 장소를 탐색하고, 나만의 코스를 구성해 공유할 수 있는 서비스입니다.
네이버 장소 검색을 통해 원하는 장소를 추가하고, 드래그 앤 드롭으로 방문 순서를 자유롭게 구성할 수 있습니다. 완성된 코스는 지도 기반으로 시각화되며, 도보·대중교통 경로를 구간별로 안내합니다. 또한 URL 공유 시 OG 메타 정보를 포함해, 카카오톡 등에서 직관적인 미리보기가 제공됩니다.
Supabase(PostgreSQL + Auth + RLS)를 활용해 백엔드를 직접 설계했으며, 인증 기반 데이터 접근 제어와 세션 유지 방식까지 고려해 실제 서비스 수준의 구조를 구현했습니다.
개발 과정에서 Google Maps, TMap, 네이버 검색 API 등 다양한 외부 API를 연동하며 CORS 처리, 서버/클라이언트 환경 분리, 인증 방식 차이를 직접 경험했고, Next.js App Router의 generateMetadata를 활용해 SSR 기반 OG 메타 생성까지 구현했습니다.

트러블슈팅
증상

useSearchParams()를 사용하는 로그인 페이지에서 Error occurred prerendering page "/login" 오류가 발생하며 Vercel 빌드가 실패했습니다.

원인

클라이언트 전용 훅인 useSearchParams()가 <Suspense> 없이 정적 프리렌더링 대상에 포함되면서, 빌드 시점에 실행되어 오류가 발생했습니다.

해결

로그인 폼을 클라이언트 컴포넌트(LoginForm.tsx)로 분리하고, page.tsx에서 <Suspense>로 감싸 렌더링 시점을 제어했습니다.

결과

프리렌더링 오류를 방지하여 빌드가 정상적으로 완료되었고, 안정적으로 배포할 수 있도록 개선했습니다.

증상

코스 편집 화면에서 장소 순서를 드래그로 변경하려 하면 드래그가 되지 않고 화면 스크롤만 발생. 드래그 핸들(이미지) 길게 누를 경우 이미지가 새 탭으로 열리거나 저장 팝업이 뜨는 문제도 발생.

원인

@dnd-kit/core 기본 PointerSensor가 마우스 기반이라 모바일 터치를 스크롤과 구분하지 못함. <img> 요소의 long-press 기본 동작이 드래그 핸들에 간섭하고, touch-action 미설정으로 드래그 중 스크롤이 재개되는 문제가 복합적으로 작용.

해결

TouchSensor를 추가하고 activationConstraint(delay: 250ms, tolerance: 5)로 스크롤과 드래그를 구분. 핸들에 touch-action: none 적용, 이미지에 draggable={false}·pointer-events: none으로 기본 드래그 비활성화. onContextMenu preventDefault와 -webkit-touch-callout: none으로 long-press 메뉴 차단.

아이디어를 실제로 동작하는 서비스로 구현하는 과정에서 가치를 느끼며, 사용자 경험에 영향을 주는 디테일까지 집요하게 다듬습니다.

결국 해답을 만들어내는 과정은 즐겁다

음악을 전공했지만, 어려서부터 다양한 분야에 관심이 많았고 특히 컴퓨터를 다루는 일에 흥미를 느껴 개인 홈페이지를 제작하며 자연스럽게 프론트엔드와 가까워졌습니다. 이후 대학 교양 수업을 통해 처음 프로그래밍을 접했고, 인간의 언어와는 다른 논리적 언어로 요구사항을 구현해 나가는 과정에 큰 매력을 느꼈습니다.

웹 퍼블리싱과 프론트엔드 교육 과정을 거치며 개발을 본격적으로 배우는 과정에서, 처음에는 문제 해결의 방향조차 보이지 않는 막막함을 자주 경험했습니다. 그러나 시행착오를 통해 원인을 분석하고 해결 방법을 찾아가는 과정 자체에서 큰 성취감과 재미를 느끼게 되었고, 이를 계기로 개발자로서의 커리어를 선택하게 되었습니다.

특히 프론트엔드는 사용자와 가장 가까운 영역에서 경험을 설계하고 개선할 수 있다는 점에서 매력을 느꼈습니다. 사용자의 입장에서 더 직관적이고 편리한 흐름을 고민하고 이를 실제 기능으로 구현하는 과정은, 타인의 경험을 중요하게 생각하는 저의 성향과도 잘 맞았습니다.

모두가 함께 나아가도록 방향을 잡고 조율하는 일

웹 프론트엔드 엔지니어 부트캠프 과정에서 두 차례의 팀 프로젝트를 수행하며 각각 PL과 PM 역할을 맡았습니다. 프로젝트 초반에는 팀원 간 참여도와 작업 속도의 차이로 인해 협업이 원활하지 않은 상황이 발생했고, 특히 일부 팀원의 소극적인 참여로 일정 지연이 우려되는 문제가 있었습니다.

이 문제를 해결하기 위해 각 팀원의 진행 상황을 지속적으로 확인하고, 개인의 속도와 상황을 고려해 역할을 재조정했습니다. 또한 필요한 부분에서는 직접 도움을 주거나 작업 방향을 구체적으로 제시하며, 팀원들이 프로젝트에 끝까지 참여할 수 있도록 독려했습니다. 동시에 전체 일정이 지체되지 않도록 주요 기능의 우선순위를 정리하고, 문제 발생 시 빠르게 원인을 파악해 해결 방안을 공유했습니다.

그 결과 프로젝트를 안정적으로 마무리할 수 있었으며, 팀 간 협업 흐름도 점차 개선되었습니다. 이 경험을 통해 프로젝트는 개인의 역량만으로 완성되는 것이 아니라, 팀 전체의 상황을 고려한 조율과 방향 설정이 필수적이라는 것을 배웠습니다.

문제를 구조적으로 해결하고, 끝까지 책임지고 완수하는 개발자

팀 프로젝트를 진행하며 기술적인 문제나 일정 지연 요소가 발생했을 때, 단순히 상황을 공유하는 데 그치지 않고 원인을 빠르게 분석하고 해결 방안을 제시하며 프로젝트가 지속적으로 나아갈 수 있도록 했습니다. PL과 PM 역할을 수행하며 팀원 간 진행 상황과 협업 흐름을 꾸준히 점검하고, 필요한 경우 역할을 조율하거나 직접 도움을 주며 팀 전체의 완성도를 높이는 데 집중했습니다.

이러한 문제 해결 과정의 기반에는 새로운 기술을 빠르게 이해하고, 이를 실제 구현으로 연결하는 학습 능력이 있습니다. 낯선 기술을 접하더라도 개념을 빠르게 정리하고 프로젝트에 적용하며 문제를 해결해왔고, 이를 통해 개발 역량을 지속적으로 확장해왔습니다.

팀과 서비스의 방향을 함께 설계하는 개발자

팀과 서비스의 방향을 함께 고민하고, 문제 해결 과정에 적극적으로 기여하며 긍정적인 영향을 줄 수 있는 개발자로 성장하고자 합니다. 단순히 기능을 구현하는 것을 넘어, 사용자가 실제로 어떤 불편을 겪고 있는지 고민하고 이를 개선하는 과정에서 가치를 만드는 프론트엔드 개발자가 되는 것을 목표로 하고 있습니다.
